# Boundary review, 8 September 2026

Reviewed the compiler driver, HIR construction, LIR ownership, and runtime I/O at
`39d549f`. The common failure pattern was a rule implemented separately at several
call sites. Later edits extended one path while leaving another with older assumptions.
The histories below establish what changed; the explanation of the editing process
is an inference from those changes.

## Changes in this review

### Paths belong to a compilation request

A library caller supplying a working directory still had relative source and output
paths resolved against the process directory. The CLI concealed this by joining the
paths itself. Native depfile paths had the same problem: a header found through a
relative `CPATH` compiled successfully, but its cache dependency was subsequently
looked up in the wrong directory. Repeated unchanged builds invoked the C compiler
again.

Commit `9494e71` introduced explicit process settings and request construction while
retaining caller-side path resolution. This left the constructor's apparent contract
stronger than its implementation. Depfile consumption similarly passed compiler-relative
names into filesystem operations without preserving their origin.

`compiler/request.rs` now owns request validation, path resolution, and executable
naming. The CLI only parses the selector and options. The native dependency reader
resolves names against the compiler's working directory before returning paths to
the cache. Tests construct requests from a different directory and observe actual
compiler invocation counts before and after a header edit.

### Image validation precedes file I/O

Writing a one-pixel PNG to `/dev/full` returned success. Passing eight bytes for a
four-byte image passed Rust-side validation, then failed inside the encoder after
creating a partial file. The C entry point also used saturating size arithmetic
before constructing a raw slice, which does not establish Rust's slice length bound.

These paths originated together in `8ab07f3`. Each entry point computed its own
layout, and encoding treated buffered writes as completed output. The abstraction
hid both the encoder's exact-length requirement and errors deferred to destruction.

A private `PixelLayout` checks dimensions, channels, stride, and byte length. Both
entry points use its packed pixel view before opening the destination. The encoder
accepts a writer and explicitly finishes it. A failing writer tests completion errors
without depending on a special device; round trips exercise excess bytes and row padding.

### Value projection has one ownership rule

Verified LIR using `AccessDynamic` skipped the result copy and container destruction
performed by `AccessStatic`. Equivalent managed array projections produced different
destructor counts. Both ownership decisions had separately listed static access when
shared ownership was introduced in `6fe990f`.

C lowering now classifies value projections once and uses that decision for both
result copying and consumed-argument cleanup. A native regression constructs both
forms through the public LIR API, covering an operation source lowering does not
normally emit for owned array values.

## Remaining design findings

### Initialization state is lost through a stored pointer

This program was accepted and verified, then crashed with SIGSEGV in a native Linux build:

```resin
export { main };
struct Owned { drops: Ptr<int> };
impl Owned {
    def drop(self: Ptr<Owned>) = { self.drops.* := self.drops.* + 1; };
}
def main() -> int = {
    var drops = 0;
    {
        var value: Owned;
        var pointer = &value;
        pointer.* := Owned { drops = &drops };
    };
    drops
};
```

The C backend attaches an initialization flag to some address expressions. Storing
an address in a pointer local loses that flag: the later store destroys uninitialized
memory and does not mark the owner live. Commit `6fe990f` preserved this metadata over
control-flow edges, but raw pointer storage and calls do not preserve it.

A follow-up must distinguish initializing storage from replacing a live value in LIR
and specify which addresses can escape before initialization. Merely propagating one
more temporary flag leaves the same problem at calls and aggregate fields. Rejecting
all uninitialized addresses would also break ordinary foreign output parameters.
This review leaves that language and LIR decision unchanged.

### Method registration bypasses result inference

```resin
struct Box { value: int };
impl Box {
    def read(self: Box) -> _ = { self.value };
}
```

This fails with “type holes are only allowed in local annotations and function
results.” Method predeclaration calls the concrete type evaluator before ordinary
function checking can infer the result. The early registration introduced in
`d22aff5` survived the two-pass rewrite in `2d6823d` and the crate split in `df96c26`.

A follow-up should keep pending method signatures in the checker, discover precise
call dependencies after resolving receivers, and publish concrete declarations after
solving. Grouping every method with the same spelling would incorrectly couple
unrelated types and could let callers choose a method's default types. This requires
changing dependency discovery, beyond the completed boundary changes above.
